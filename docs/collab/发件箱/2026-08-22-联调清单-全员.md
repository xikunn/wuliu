## 1. 环境前置（后端 / 运维）

### 1.1 工具

| 工具 | 版本要求 | 检查命令 |
|------|----------|----------|
| JDK | **21** | `java -version` |
| Maven | 3.8+ | `mvn -version` |
| Docker | 可运行 daemon | `docker ps` |
| Node | 18+ | `node -v` |

### 1.2 基础设施（Docker）

参考 `smart-street-light-master/docker.sh`：

```bash
# PostgreSQL（pgvector）
docker run -d --name pg17-vector -p 5432:5432 \
  -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=123456 \
  pgvector/pgvector:pg17

# EMQX
docker run -d --name emqx -p 1883:1883 -p 18083:18083 emqx:latest
```

### 1.3 数据库

```bash
# 在 PG 中执行
psql -U postgres -h localhost -f smart-street-light-master/sql/schema.sql
# 可选测试数据
psql -U postgres -h localhost -f smart-street-light-master/sql/test-data.sql
```

### 1.4 后端配置

1. 复制 `smart-street-light-master/src/main/resources/application-secret-example.yml`  
   → `application-secret.yml`（**勿提交 Git**）
2. 修改 `application.yml` 中 DB/MQTT 地址为 `localhost`（若不用远程 `10.59.47.188`）：

```yaml
spring.datasource.url: jdbc:postgresql://localhost:5432/smart-street-light
mqtt.broker-url: tcp://localhost:1883
```

3. `application-secret.yml` 至少填写：

| 键 | 说明 |
|----|------|
| `spring.datasource.password` | 与 Docker PG 一致 |
| `jwt.secret-key` | JWT 签名 |
| `mqtt.username` / `mqtt.password` | EMQX 账号（示例 admin/123456） |
| `llm.api-key` | 仅 AI 模块需要；联调 MVP 可暂空（chat 会失败） |

### 1.5 启动后端

```bash
cd smart-street-light-master
mvn package -DskipTests
java -jar target/smart-street-light-0.0.1-SNAPSHOT.jar
```

验收：`curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/users/login` → 405 或 400 均可（说明端口在监听）。

## 2. 前端联调（前端）

### 2.1 安装与配置

```bash
cd web
npm install
cp .env.example .env.local
# 确认：VITE_API_MODE=http，VITE_API_BASE=（空），VITE_WS_BASE=ws://localhost:8080
npm run dev
```

浏览器：http://localhost:5173

### 2.2 必测用例

| # | 步骤 | 期望 |
|---|------|------|
| F1 | 注册新用户 / 或用 test-data 账号登录 | `code=200`，Header 带 `token` |
| F2 | Dashboard | 设备统计数字与 `GET /devices/statistics` 一致 |
| F3 | 设备页添加设备 | `deviceSn` 与板端 MQTT 标识一致 |
| F4 | 手动开/关灯 | `POST /devices/{id}/switch` 成功，控制日志有 `MANUAL_ON/OFF` |
| F5 | 光照页 | **当天**趋势有数据（已改为动态日期范围） |
| F6 | 告警页解决 ACTIVE | `PUT /alarm-logs/{id}/resolve` |
| F7 | ADMIN 登录改阈值 | `PUT /threshold-config` |
| F8 | 实时光照 / 告警 toast | STOMP 连接 LIVE；板端或 Mock 上报后 Dashboard/弹窗更新 |

### 2.3 已知限制（联调时勿误判为前端 bug）

- JWT **15 分钟**过期，无 refresh；过期后需重新登录（见对齐审计 §4.5）
- 后端**未做 ADMIN 角色拦截**；阈值页仅前端隐藏
- 硬件 HTTP 降级接口需 JWT；**板端应走 MQTT**（见 §3）

## 3. 板端联调（端侧）

### 3.1 工程

- 导入：`D:\ohos\bearpi-hm_nano` 或 `firmware/bearpi-hm_nano`（junction）
- 详见 `firmware/README.md`

### 3.2 MQTT Topic（与后端一致）

| Topic | 方向 | Payload 示例 |
|-------|------|--------------|
| `smart-light/{deviceSn}/light` | 板 → 云 | `{"deviceSn":"SN001","lightIntensity":850.5,"timestamp":"2026-08-22 14:00:00"}` |
| `smart-light/{deviceSn}/status` | 板 → 云 | `{"deviceSn":"SN001","status":"ON","timestamp":"..."}` |
| `smart-light/{deviceSn}/alarm` | 板 → 云 | `{"deviceSn":"SN001","alarmType":"LIGHT_ABNORMAL","message":"..."}` |
| `smart-light/{deviceSn}/command` | 云 → 板 | `{"command":"AUTO_ON","timestamp":"..."}` |

`command` 枚举：`AUTO_ON` / `AUTO_OFF` / `MANUAL_ON` / `MANUAL_OFF`

### 3.3 板端必做（Must #3）

| # | 任务 | 验收 |
|---|------|------|
| B1 | EMQX 连接（username/password 与 secret 一致） | 控制台可见客户端在线 |
| B2 | 周期 publish `.../light` | 后端 DB `light_readings` 有记录；前端 WS 实时光照更新 |
| B3 | subscribe `.../command` | 收到 `MANUAL_ON` 后 GPIO/LED 动作，并 publish `.../status` |
| B4 | `deviceSn` 与 Web 添加设备时的 SN **完全一致** | 后端能关联设备 |

### 3.4 可选

- publish `.../alarm` 验证前端告警 toast
- 光照低于阈值验证 `AUTO_ON` 与 `DEVICE_STATUS_CHANGED` WS

## 5. 端到端验收（全员）

**最小闭环定义（Must 完成标准）：**

```text
[ BearPi ] --MQTT light--> [ EMQX ] --> [ Spring Boot ] --WS--> [ 灯廊 Dashboard ]
                ^                              |
                +-------- MQTT command --------+  （手动开关或阈值 AUTO_ON）
```

勾选即联调通过：

- [ ] Docker PG + EMQX 运行
- [ ] `schema.sql` 已执行，后端 :8080 正常
- [ ] Web `VITE_API_MODE=http`，F1–F7 通过
- [ ] 板端 B1–B3 通过（或 MQTT 工具模拟 light + 收 command）
- [ ] 一条真实 `deviceSn` 贯穿 Web 添加设备 ↔ MQTT ↔ DB
